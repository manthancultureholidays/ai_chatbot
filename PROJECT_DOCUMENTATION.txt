PROJECT OVERVIEW
================================================================================

Project Name: AI Travel Chatbot
Type: Full-Stack Web Application with RAG (Retrieval-Augmented Generation)
Architecture: Client-Server with LLM Integration
Purpose: Intelligent Q&A system for travel agent data analysis

TECHNOLOGY STACK
================================================================================

Backend:
- Runtime: Node.js
- Framework: Express.js v5.2.1
- Database: SQLite3 v5.1.7
- LLM Integration: Ollama (with fallback support)
- Logging: Winston v3.19.0
- Validation: Express-validator v7.3.1
- Rate Limiting: Express-rate-limit v8.2.1
- HTTP Client: Axios v1.13.5

Frontend:
- Framework: React v19.2.4
- UI: Custom CSS with responsive design
- Testing: Jest, React Testing Library

Key Features:
- RAG-based question answering
- Vector search with fuzzy matching
- In-memory caching
- Real-time streaming responses
- Data quality analysis
- Login pattern detection
- Multi-LLM fallback support

CORE COMPONENTS DOCUMENTATION
================================================================================

1. SERVER (server.js)
--------------------------------------------------------------------------------
Entry point for the backend application.

Key Responsibilities:
- Initialize Express server
- Configure middleware (CORS, body-parser, rate limiting)
- Initialize vector service and cache
- Setup logging with Morgan
- Handle graceful shutdown

Configuration:
- Port: 5000 (default)
- Rate Limit: 100 requests per 15 minutes per IP
- CORS: Enabled for all origins

Startup Sequence:
1. Load environment variables
2. Initialize vector service
3. Connect to database
4. Setup middleware
5. Register routes
6. Start listening on port


2. VECTOR SERVICE (services/vectorService.js)
--------------------------------------------------------------------------------
Core search and retrieval engine using in-memory indexing.

Features:
- Multi-index search (email, ID, name, company, nationality)
- Fuzzy matching with Levenshtein distance
- Token-based inverted index
- Login history integration
- Caching support

Indexes:
- agentByEmail: Map<email, agent>
- agentByID: Map<agentID, agent>
- agentByName: Map<name, agent>
- agentByCompany: Map<company, [agents]>
- agentByNationality: Map<nationality, [agents]>
- loginsByIdentifier: Map<identifier, [logins]>
- searchIndex: Map<token, Set<agentIDs>>

Search Strategy:
1. Extract identifiers (emails, agent IDs, login IDs)
2. Direct lookup in indexes (O(1))
3. Company name matching (exact + fuzzy)
4. Nationality matching
5. Name matching (exact + fuzzy)
6. Token-based search
7. Return top results with scores

Fuzzy Matching:
- Algorithm: Levenshtein distance
- Threshold: 0.7 (configurable)
- Applied to: names, companies, tokens


3. LLM SERVICE (services/llmService.js)
--------------------------------------------------------------------------------
Manages LLM integration with fallback support.

Supported LLMs:
- Primary: Ollama (local deployment)
- Fallback: vLLM or remote Ollama

Configuration (via .env):
- OLLAMA_URL: Primary Ollama endpoint
- OLLAMA_MODEL: Model name (default: llama3.2:latest)
- FALLBACK_LLM_URL: Backup LLM endpoint
- FALLBACK_LLM_TYPE: Type (ollama/vllm)
- FALLBACK_MODEL: Fallback model name
- LLM_TIMEOUT: Request timeout (30000ms)
- LLM_MAX_RETRIES: Retry attempts (2)

Features:
- Streaming responses
- Automatic retry with exponential backoff
- Graceful fallback
- Error handling

Response Flow:
1. Try primary Ollama with streaming
2. On failure, retry with exponential backoff
3. If max retries exceeded, switch to fallback
4. If all fail, throw error


4. DATA ANALYZER (services/dataAnalyzer.js)
--------------------------------------------------------------------------------
Comprehensive data quality and pattern analysis engine.

Capabilities:

A. Data Quality Checks:
   - Malformed login dates
   - Case-sensitive agent ID variants
   - Email typos (.comm instead of .com)
   - Tab characters in data
   - Spaced emails
   - Malformed JSON keys
   - Leading hyphens in agent IDs
   - Duplicate IDs

B. Login Pattern Analysis:
   - Top login agents
   - Logins by date
   - Consecutive login bursts
   - Earliest/latest logins
   - Unique agent counts
   - Login frequency analysis

C. Company Analysis:
   - Agents by company
   - Company establishment dates
   - Oldest establishments
   - Company name variations

D. Nationality Analysis:
   - Agents by nationality
   - Most frequent nationalities
   - Geographic distribution

E. Security Analysis:
   - Rapid sequential logins
   - Credential sharing detection
   - Non-standard agent IDs
   - Suspicious login patterns

Query Detection:
- Domain-specific queries (e.g., cultureholidays.com)
- Agent ID lookups
- Company lookups
- Nationality queries
- Establishment date queries
- Duplicate detection
- Cross-document matching
- Pattern searches


5. DATABASE SERVICE (services/databaseService.js)
--------------------------------------------------------------------------------
SQLite database operations wrapper.

Schema:

Table: agents
- AgentID (TEXT, PRIMARY KEY)
- Name (TEXT)
- UserName (TEXT)
- Comp_Name (TEXT)
- Nationality (TEXT)
- CreatedDate (TEXT)
- LastLogin (TEXT)
- data (TEXT) - Full JSON

Table: logins
- ID (INTEGER, PRIMARY KEY)
- AGENTID (TEXT, FOREIGN KEY)
- LOGINDATE (TEXT)
- data (TEXT) - Full JSON

Indexes:
- idx_agent_username ON agents(UserName)
- idx_agent_company ON agents(Comp_Name)
- idx_login_agentid ON logins(AGENTID)

Operations:
- connect(): Initialize database connection
- initTables(): Create tables and indexes
- insertAgent(agent): Insert/update agent
- insertLogin(login): Insert/update login
- getAgent(agentID): Retrieve agent by ID
- getLoginsByAgent(agentID): Get login history
- getAllAgents(): Retrieve all agents
- getAllLogins(): Retrieve all logins
- getAgentsWithLoginsInDateRange(): Date range query
- close(): Close connection


6. CACHE SERVICE (services/cacheService.js)
--------------------------------------------------------------------------------
In-memory caching with TTL support.

Features:
- Key-value storage
- Time-to-live (TTL) expiration
- Pattern-based invalidation
- Automatic cleanup

Configuration:
- Default TTL: 3600 seconds (1 hour)

Operations:
- get(key): Retrieve cached value
- set(key, value, ttl): Store with expiration
- del(key): Delete specific key
- invalidatePattern(pattern): Delete matching keys
- disconnect(): Clear all cache


7. QUERY CONTROLLER (controllers/queryController.js)
--------------------------------------------------------------------------------
Main request handler for Q&A endpoint.

Request Flow:
1. Validate input (1-1000 characters, allowed characters)
2. Check if analytical query (data quality/patterns)
3. If analytical, return direct answer
4. Otherwise, perform vector search
5. If no results, load all agents as fallback
6. Build optimized prompt with context
7. Stream LLM response
8. Handle errors with fallback extraction

Prompt Engineering:
- Role: Expert data analyst
- Rules: 7 specific guidelines
- Context: Retrieved documents
- Format: Structured with examples

Error Handling:
- Validation errors: 400 with details
- Service errors: Logged and handled
- LLM failures: Fallback to answer extractor
- No data: Graceful message


8. ANSWER EXTRACTOR (utils/answerExtractor.js)
--------------------------------------------------------------------------------
Fallback answer generation without LLM.

Query Types Supported:
- Count queries (total, how many)
- Login queries (last login, login date)
- Company queries (works at, employed)
- Email queries (contact, email)
- Agent ID queries (identification)
- Nationality queries (country, origin)
- List queries (show all, list)

Strategy:
1. Parse agent data from context
2. Detect query type
3. Extract relevant information
4. Format structured response

Parsing:
- Split context by '---' delimiter
- Extract key-value pairs
- Build agent objects
- Filter valid entries

Response Format:

  "error": {

  }
}

Logging:
- All errors logged with context
- Stack traces for debugging
- IP and request details

API DOCUMENTATION
================================================================================

Base URL: http://localhost:5000/api

1. Ask Question
--------------------------------------------------------------------------------
POST /api/ask

Request:
{
  "question": "string (1-1000 chars)"
}

Response: text/plain (streaming)
- Streams answer in real-time
- No JSON wrapper
- Plain text response

Status Codes:
- 200: Success
- 400: Validation error
- 429: Rate limit exceeded
- 500: Server error

Example:
curl -X POST http://localhost:5000/api/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "How many agents are there?"}'


2. Get Statistics
--------------------------------------------------------------------------------
GET /api/stats

Response:
{
  "totalAgents": 150,
  "companies": 45,
  "nationalities": 12
}

Status Codes:
- 200: Success
- 500: Server error

Example:
curl http://localhost:5000/api/stats

INSTALLATION & SETUP
================================================================================

Prerequisites:
- Node.js v16+ 
- npm or yarn

2. Install dependencies

3. Create .env file

TROUBLESHOOTING
================================================================================

Common Issues:

1. Server won't start
   - Check port availability
   - Verify .env configuration
   - Check logs/error.log

2. LLM not responding
   - Verify Ollama is running
   - Check OLLAMA_URL
   - Test fallback configuration

3. No search results
   - Verify data files exist
   - Check database connection
   - Review vector service logs

4. Frontend can't connect
   - Verify backend is running
   - Check CORS configuration
   - Verify API_URL in frontend

5. Rate limit errors
   - Wait 15 minutes
   - Adjust rate limit settings
   - Check IP address

Debug Mode:
- Set LOG_LEVEL=debug in .env
- Check logs/combined.log
- Enable console logging
